01 / SYSTEM OVERVIEW

What is Arety RCB 1.2?

RCB (Real Cognition Brain) is the architecture. Arety RCB 1.2 is one specific served configuration of that architecture, selected through the Arety API as arety-rcb-1.2. Its design separates interpretation, computation, comparison, context, memory and knowledge into cooperating nodes connected by a full-mesh message bus.

RCB 1.2 contains no outside language model in its served configuration. Every node uses Arety's native processors. An alternative external-model mode and a deterministic test mock exist in the package, but neither is enabled in this configuration.

ARCHITECTURE

Distributed responsibilities

Specialized nodes cooperate on a thought. Full mesh describes reachability; routing determines which nodes actually participate.

VERIFICATION

Check before composition

Arithmetic, algebra and factual answers pass through comparison before the final answer is composed.

STATE

Context beyond one turn

Chat context and user context are separate. User facts are stored per account or guest session.

SCOPE

A focused research system

Its demonstrated tasks are arithmetic, algebra, factual lookup, taught facts and short conversation—not general-purpose language generation.

Terminology: RCB is the architecture and has no version number. RVTCB is the software package that implements it with virtual nodes (package version 0.1.x; protocol rvtcb/0.1). RPTCB refers to the same architecture instantiated on physical nodes.

Thought lifecycle

Context → Interpret → Recall → Route → Compute / Reason → Compare → Compose → Store

A request becomes a Thought record. It retains the original prompt, detected intent, expression and computed value when relevant, verification verdict and confidence, participating nodes, exchanged messages, per-step timings and final answer.

04 / COMPUTATION & COMPARISON

Independent checks before an answer

Arithmetic

The Language node extracts an expression. Processor-ALU compiles it into a micro-program and executes it on its ALU, which contains a 64-bit integer unit, an IEEE double unit, a register file and Zero, Negative, Overflow and Error flags. Comparison replays the micro-program on its own ALU and independently evaluates the expression with exact rational arithmetic using Python fractions. The two results are compared before composition.

Algebra

Processor-ALU solves linear and quadratic equations and supports symbolic simplification, expansion and factorisation. Comparison substitutes the proposed solution back into the original equation and checks whether it agrees.

Factual consensus

When consensus is enabled, Processor-ALU asks every knowledge sub-node, shares initial findings so nodes can follow up on mentioned entities, and weighs candidate facts using source trust and confidence. Supporting evidence can pool when candidates agree. Comparison checks grounding and consistency. This is weighted evidence, not simple majority voting.

Example: 3x - 7 = 11

Processor-ALU: x = 6
Comparison:     substitute 6 into 3x - 7
                3(6) - 7 = 11
Verdict:        agree
Precision boundary: integer operations are exact within the supported 64-bit range. Values beyond that range wrap with the Overflow flag. True division uses IEEE double precision and loses integer precision beyond 2^53.

Up to 20 requests per minute per client address. Conversation state is scoped to the caller's session and address.

OpenAI-compatible request shape. Personal keys use the account's memory and are not rate-limited, according to the paper.

MCP

Streamable HTTP MCP endpoint. Tools include ask_arety, reset_session, search and fetch.

TRAINING

/train

Accepts fact batches, validates entries and routes world facts and user facts to their respective stores.

curl https://tests.arety.cloud/v1/think \
  -H "Content-Type: application/json" \
  -d '{"prompt":"What is 123456789 * 987654321?","session":"demo"}'

curl https://tests.arety.cloud/v1/chat/completions \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"arety-rcb-1.2","messages":[{"role":"user","content":"What is 2^20 - 1?"}]}'
The public API returns the model identifier and answer. Internal node traces and comparison verdicts are not returned by the public API.

Conversation and load measurements

  • 300-turn conversation: 100/100 references to “that” resolved correctly through turn 299; Context retained the most recent 200 turns; resident memory grew by 12.8 MB.
  • 500 separate one-turn conversations: 3.3 seconds total, 15.7 MB resident memory, approximately 32.2 KB per open conversation.
  • Sequential in-process throughput: 138 arithmetic thoughts/s, 36.9 factual thoughts/s (repeated prompts partly served from evidence cache), 116.2 conversational thoughts/s.
  • Public endpoint concurrency test: throughput reached 3.26 requests/s at eight clients, with increasing tail latency. One brain serializes thoughts behind a single-thought lock.
The public endpoint's approximately 3 requests/s ceiling is a current deployment constraint, not a measured limit of a multi-machine architecture. One brain per worker has been identified as a next step but was not built in the paper.
07 / LIMITATIONS & RESPONSIBLE USE

What RCB 1.2 does not yet do

  • Narrow competence: arithmetic, algebra, factual lookup, taught facts and short conversation. It does not translate, summarise, write long-form prose or reliably handle multi-part instructions.
  • Routing is a fixed intent table; complexity, capability and load are not considered.
  • Knowledge coverage is bounded by its indexed databases; two factual items were missing in the benchmark.
  • Same-name entities can cause unrelated facts to leak into factual answers during consensus follow-up.
  • Some possessive phrasings can store taught facts under the wrong subject.
  • An unknown personal-memory question did not abstain correctly in one transcript.
  • The served deployment runs in one process and serializes thoughts; no multi-machine deployment was measured.
  • True division uses IEEE doubles; integers beyond 64-bit range overflow.

Defects fixed during evidence collection

Commit a7557fc fixed large-integer rounding in answer composition and 64-bit boundary inconsistencies involving division, remainder, negation and absolute value of the minimum signed integer. The paper records the added parity tests.

Privacy and safety

User context is persistent. The served system describes per-account or per-guest-session isolation, account visibility and deletion controls, and 14-day guest-session retention. Operators of other deployments should provide transparency, inspection/deletion controls and isolation. Knowledge and user-taught facts are data, not instructions, and their sources should remain traceable. Comparison checks correctness, not acceptability; it is not a safety filter.

No claim is made that RCB is AGI, conscious, or generally superior to large language models. The claims are limited to the recorded tasks and measurements.
